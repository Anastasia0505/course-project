РОЗДІЛ 12. Обрана методологія розробки

12.1. Огляд можливих методологій:

1. Waterfall (Каскадна модель):
   - Чітка послідовність етапів
   - Кожен етап завершується документально
   - Мінуси: важко вносити зміни, довгий цикл

2. Agile (Гнучка розробка):
   - Ітеративна розробка короткими циклами
   - Можливість змінювати вимоги в процесі
   - Мінуси: вимагає постійної комунікації

3. Scrum (різновид Agile):
   - Робота спринтами (2-4 тижні)
   - Щоденні зустрічі команди
   - Мінуси: складно для одного розробника

12.2. Обрана методологія:

Для даного курсового проекту обрано спрощену Agile-методологію.

Обґрунтування вибору:
1. Проект виконується одним розробником (студентом)
2. Вимоги можуть змінюватися в процесі навчання
3. Можливість поступового додавання функцій
4. Гнучкість у плануванні часу

12.3. Етапи розробки (спринти):

Спринт 1 (Тиждень 1-2):
- Налаштування середовища розробки
- Створення бази даних
- Реєстрація та авторизація користувачів

Спринт 2 (Тиждень 3-4):
- CRUD операції для завдань (створення, читання, оновлення, видалення)
- Базовий інтерфейс користувача

Спринт 3 (Тиждень 5-6):
- Фільтрація та пошук завдань
- Адмін-панель
- Тестування та виправлення помилок

Спринт 4 (Тиждень 7-8):
- Документування
- Підготовка до захисту

12.4. Інструменти розробки:

- Система контролю версій: Git + GitHub
- Текстовий редактор: VS Code
- База даних: MySQL
- Мова програмування: (на вибір — PHP/Python/JavaScript)
- Управління завданнями: GitHub Issues / Trello

12.5. Висновок:

Обрана методологія дозволяє гнучко розробляти проект,
вносити зміни в процесі навчання та поступово додавати
новий функціонал без повної переробки системи.
