РОЗДІЛ 8. Обґрунтування вибору типу бази даних

8.1. Вимоги до системи зберігання даних:

- Зберігання структурованих даних (користувачі, завдання)
- Підтримка транзакцій (ACID)
- Зв'язки між таблицями (користувач → завдання)
- Швидкий пошук за індексами
- Масштабованість для зростання кількості користувачів

8.2. Розгляд варіантів:

Варіант 1: Реляційна база даних (MySQL/PostgreSQL)
Переваги:
+ Чітка структура даних
+ Підтримка зовнішніх ключів
+ Транзакції та цілісність даних
+ Широка підтримка та документація
Недоліки:
- Менша гнучкість при зміні структури

Варіант 2: NoSQL база даних (MongoDB)
Переваги:
+ Гнучка схема даних
+ Горизонтальна масштабованість
Недоліки:
- Відсутність транзакцій (у старих версіях)
- Менша цілісність даних

Варіант 3: SQLite
Переваги:
+ Простота розгортання
+ Не потребує сервера
Недоліки:
- Не підходить для високонавантажених систем
- Обмежена масштабованість

8.3. Вибір та обґрунтування:

Обрано: MySQL (реляційна база даних)

Обґрунтування:
1. Дані системи мають чітку структуровану форму
2. Необхідні зв'язки між таблицями (один-до-багатьох)
3. Потрібна цілісність даних (транзакції)
4. MySQL є надійним рішенням для веб-додатків
5. Широка підтримка хостинг-провайдерів
6. Безкоштовна ліцензія (Community Edition)

8.4. Альтернатива:

Для майбутнього масштабування можлива міграція на PostgreSQL
для розширеного функціоналу та кращої продуктивності.
