РОЗДІЛ 9. Аналіз можливостей масштабування системи

9.1. Поточні вимоги до системи:

Очікуване навантаження для навчального проекту:
- Кількість користувачів: до 100 осіб
- Кількість завдань на користувача: до 50
- Одночасних користувачів: до 10-15
- Обсяг даних: до 5000 записів у таблиці tasks

9.2. Реалістичні заходи масштабування:

1. Оптимізація бази даних:
   - Додавання індексів до часто використовуваних полів:
     * users.email — для швидкого пошуку при вході
     * tasks.user_id — для швидкої вибірки завдань користувача
     * tasks.status — для фільтрації за статусом
   - Використання типів даних оптимального розміру
   - Регулярне очищення тестових даних

2. Кешування на рівні додатку:
   - Збереження сесії користувача в пам'яті сервера
   - Кешування результатів частих запитів (наприклад, список завдань)
   - Використання простого кешу в пам'яті (без Redis)

3. Оптимізація коду:
   - Використання підготовлених запитів (prepared statements)
   - Уникнення N+1 запитів при отриманні даних
   - Пагінація списків (по 20-50 записів на сторінку)

4. Оптимізація фронтенду:
   - Мініфікація CSS/JS файлів
   - Стиснення зображень
   - Ліниве завантаження (lazy loading) при великих списках

9.3. Просте горизонтальне масштабування :

Якщо кількість користувачів зросте:
- Винесення статичних файлів на безкоштовний CDN (наприклад, GitHub Pages)
- Використання безкоштовного хостингу з балансуванням (Render, Railway)
- Налаштування реплікації MySQL на другому сервері (опціонально)

9.4. Обмеження навчального проекту:

Для цілей курсової роботи достатньо:
- Одного віртуального сервера (або локального розгортання)
- Одного екземпляра MySQL
- Базової оптимізації запитів
